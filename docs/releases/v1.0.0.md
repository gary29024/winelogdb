# WineLogDB v1.0.0

**Release date:** 2026-08-31

WineLogDB 1.0 is the first stable release of the private, Cloudflare-native wine notebook. It consolidates all merged work from the initial application scaffold through PR #185 into a supported baseline for future releases.

This release is centered on one workflow: capture a bottle or tasting quickly, preserve the original evidence, reconcile it to stable wine identities, and make the resulting journal useful later through research, collections, Passport and Insights.

## Highlights

### Scan and log wine in the way the moment requires

- **Single Wine** recognition for one bottle, including multi-photo review and editable AI results.
- **Batch Scan** for many bottles with asynchronous, resumable recognition, recovery for interrupted/stalled jobs, confirmation history and current saved-wine names.
- **Group Photo** recognition for several bottles in one image, with per-bottle crops, source-photo retention, cross-device resume and sequential review.
- Selective escalation of uncertain recognition to the stronger Gemini model while retaining a usable primary result if escalation fails.
- Add and remove photos from wines that already exist, and attach a newly scanned photo to a matching wine from the same tasting instead of creating a duplicate.

### Tastings are first-class records

- Start, end, reopen and browse live tasting sessions.
- New wines automatically join the open tasting; existing journal wines can be attached retrospectively.
- Tasting pages retain their lineup and photographed wine-list documents across refreshes/devices.
- Printed wine lists can be saved first and read only when requested, then reviewed page by page.
- Parsed list rows can fill prices on already-logged wines, be manually matched when the printed wording differs, or create genuinely missing wines.
- Saved wine-list readings survive locally while review is unfinished, avoiding unnecessary repeat AI reads.

### Stable producer, cuvée and place identity

- Canonical producer and cuvée identities with aliases, merge/reconciliation flows and catalogue-backed matching.
- Release-family handling for numbered/non-vintage families such as Krug editions and Henri Giraud MV / reserve-span releases.
- Unicode-safe identity keys for names written in Chinese, Japanese, Korean, Cyrillic and other scripts, including repair of earlier ASCII-only collisions.
- A place hierarchy normalizes country, region, appellation, denomination and Burgundy cru tier rather than trusting whichever recognition field a place happened to arrive in.
- Raw recognized region/appellation readings are retained as **As recorded** evidence, while later corrections can replace stale readings.
- Explicit user choices for producer/cuvée primary names are respected without weakening identity matching.

### Deep Search is evidence-first

- Wine and producer research uses Google Search grounding and reusable scope-level caching.
- Claim-level provenance maps grounded source segments to individual statements.
- Precise technical claims such as percentages, durations, dosage, dates, temperatures and vessel sizes require direct evidence before a scope is accepted.
- Independent source conflicts are preserved and labelled rather than silently resolved.
- Failed scopes retry selectively, with the rejection reason carried into the retry.
- Grounding health is observed per model, and research avoids combinations that silently cancel grounding.
- Producer research supports bounded batch campaigns, history, stalled-run recovery and reduced search/request cost.

### Passport, Insights and Wine Collections

- Passport is driven by the journal, including a country map, progress milestones, recent tastings and semantic grape/style presentation.
- Insights emphasizes signals that do not require ratings: repeat producers, favourites, exploration, cadence, drinking age and wine mix, while rating/structure analysis appears when coverage is meaningful.
- Wine Collections provide curated checklist achievements plus user-created smart catalogue and manual collections.
- Collection matching is identity-aware, retroactive and cached behind revision invalidation; historic-vintage collections support controlled matching modes.
- The curated collection set expanded across Bordeaux, Burgundy, Champagne, DRC, Barolo, Tuscany, Napa, Oregon, Washington, Australia, New Zealand and other benchmark themes.

### Cost-aware Cloudflare architecture

- React frontend + Hono Worker, D1 metadata, private R2 imagery and Cloudflare Queues.
- Synchronous recognition routes through Cloudflare AI Gateway / Vertex when configured; asynchronous Batch Scan and research use Vertex Flex PayGo.
- D1 reads/writes were reduced through revision caches, guarded writes, covering indexes, conditional requests and backed-off polling.
- AI usage is metered by workflow/model/tier with raw request, search and token counts; thinking tokens are included in output cost.
- Pricing uses dated model rates and service-tier multipliers, and recognition costs are reported per wine rather than per session.

### A polished installable web app

- Mobile shell sized for modern iPhones with safe-area handling, non-zooming form controls and an installable home-screen icon.
- Responsive Journal pagination, exact result counts, direct page navigation, remembered filters/search and stable multi-select images.
- Shared design tokens, action/chip hierarchy, dark mode, improved focus treatment and accessibility guards.
- Setup and GitHub-connected deployment guidance for self-hosting on Cloudflare.

## Deployment / upgrade

For a self-hosted deployment, follow `SETUP.md` and deploy with:

```bash
npm run deploy
```

That command builds the app, applies remote D1 migrations and then deploys the Worker. Do not substitute a bare `wrangler deploy` when the code includes migrations.

Existing deployments should back up D1/R2 as appropriate before a major release and then allow the migration runner to apply any outstanding migrations through `0043`.

## Known maintenance note

The geographical-indication register file records its current provenance as hand-transcribed. `npm run gi:sync` is available to refresh it from the EU eAmbrosia register in an environment that can reach that service; the drift test is designed to fail if the live register disagrees with the maintained place tree.
